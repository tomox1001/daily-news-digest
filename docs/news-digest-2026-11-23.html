欧州委員会がAIを使ったサイバー攻撃を認め人事系システムが10日超停止——FBIはAI攻撃基盤「ARTEX」で「標的選定から特権取得まで3時間未満」の侵入を警告、検知項目を公開

欧州委員会は11月19日、10月22日に最初の兆候を検知したサイバー攻撃を認め、報道官は「AI-generated cyber campaign」と表現した。The Recordによると、給与、休暇申請、医療費精算、翻訳の各サービスが10日超止まり、POLITICOはCERT-EUがオープンソースのAI攻撃基盤ARTEXの使用を特定したと報じた（委員会自身は製品名を公表していない）。FBIは11月13日付のFLASHで、ARTEXが外部のLLMをつないで偵察から侵入、永続化、横展開までを自動で進め、一部の侵入は標的選定から特権取得まで3時間未満だったと警告した。被害例として韓国の金融機関からの約6万7,000人分の個人情報流出、バックアップサービス経由での2,250超の下流テナントへのサインイン試行を挙げ、11月初旬時点で外部公開されたARTEXの管理画面は1,600超あった。FBIは検知項目として、想定外のLLM API（api.deepseek.com など）への通信、1秒未満の間隔でのテスト用データ書き込みと削除、少しずつ値を変えた失敗の連続、ポータルでの連番照会を挙げ、管理系インターフェースを信頼できるネットワークに限定することを勧めている。

🛡️ 脆弱性 11/19-20

手元で動くHTTP型MCPサーバー、閲覧中のWebサイトから操作される欠陥が2日で4件——公式Python SDKにも接続先サーバーへclient_secretを渡してしまう脆弱性

GitHub Advisory Databaseで11月19〜20日、MCPサーバーの重大な脆弱性が相次いで公開された。jupyter-mcp-server（CVE-2026-77359、critical、1.0.2以下）と@doist/todoist-mcp（CVE-2026-76807、critical、CVSS 9.3、10.3.2以下）は、HTTP型で動かしたときにHost/Originヘッダーの検査が欠けており、DNSリバインディングによって利用者が閲覧しただけの悪性サイトからJupyterの接続先を差し替えたり、Todoistのデータを書き換えたりできる。obsidian-sync-mcp（0.5.6以下）は認証トークン未設定のモードで保管庫全体を読み書きでき、k8s-mcp-server（1.1.0未満）は既定で認証なしのまま待ち受け、到達できれば誰でもKubernetesの作成・削除系ツールを実行できる。さらにMCP公式Python SDK（CVE-2026-115563、high、CVSS 7.5）は、接続先のMCPサーバーが指定した認可サーバーを検証せず、client_secretや認可コードを攻撃者側へ送ってしまう可能性があり、1.30.0または2.2.0で修正された。stdio型で使うクライアントやサーバーはいずれも影響を受けない。
